What the project does:
This project implements a simple expense tracker that processes a list of expense records. Each record contains a date, category, amount, and description. The program computes summary statistics:

-Total spending and record count
-Spending per category
-Most and least expensive items
-Expenses above the average amount

How to run it:
-python part_b_imperative.py
-python part_c_procedural.py`
-python part_d_functional.py

Imperative:
The step-by-step structure is easy to understand and logical, but the repetitive nature of the code and the lack of closed data limit its scalability

100 000 The code would still work, but making changes to it would be a nightmare, and the code itself would be very inefficient

Procedural:
Code broken down into small functions is more readable, but for very simple code, this might be overkill

100 000 The code scales well and can be modified in parts without any negative consequences

Funtional:
Fast-paced, but (for me) not very accessible—you need to know certain vocabulary

100 000 It works similarly to procedural scales, but is more memory-efficient

One thing you would do differently:
If I were to start over, I would probably focus on the functions within each group rather than on the tasks themselves. I would select similar functions from each task and work my way from the easiest to the hardest within a given group. This would make it easier to create complex functions by building on the logic derived from simpler solutions.
